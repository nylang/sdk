# Nyra SDK 1.0.5

Lint and type-owned API refactoring across the compiler, analyzer, package manager and eight ecosystem packages. Workspace YAML lint defaults and package overrides enforce reviewed coding rules. Kernel scalar constexpr faces now include mathematical factors and integer bounds; typed zero initialization and pointer nil comparisons have focused compatibility coverage.

NyraOS-facing runtime work includes checked arithmetic/range/byte utilities, unsigned and pointer atomics, explicit allocator/provider contracts, ordinary foreign C main handling, borrowed argv entry, generated C numeric definitions and production/test ObjectUnit isolation. Freestanding ntest supports consumer-owned output/counters with one/four-context RV64 execution controls. OS adoption and OS boot acceptance remain consumer work.

Native SDKs contain nyrac, nyra-analyzer and nyra for macOS arm64, macOS x86_64, Linux x86_64 and Windows x86_64. macOS x86_64 qualification uses Rosetta. macOS 14 is a deployment floor; execution on macOS 14 is not claimed. The compiler correction keeps implicit precompiled kernel runtime ABI providers during entry-import selection. A Linux-only file-open correction rejects directory descriptors before they can be mistaken for empty files. The frontend correction also canonicalizes named precompiled declaration owners before import/export conflict checks, preserving ABI link names and producer-package boundaries. Generated libraries demonstrate immutable values and instance methods. All four final native SDKs were qualified from the integrated frozen source. The complete compiler inventory is 538 regressions and 1198 compiler/dependency units on macOS/Linux, 1197 on Windows. Each compiler passed its G1/G2 fixed point and one complete G2 regression/unit campaign. The analyzer and package manager were each built once by the selected native G0 and passed their complete 30/16 owned units once. Exact unchanged native Git backend libraries can be reused after hash-bound admission. Packaging and publication preserve accepted executable bytes and receipts without repeating full suites.

Separate kernel/ntest CPU/ISA/ABI bundles and stdlib system bundles cover the reviewed 18-profile matrix. Their manifests distinguish physical, virtual/Rosetta and compile-only scope. Linux arm64/RISC-V and Windows arm64 tool worksets are compile-only evidence, not linked executable SDKs; matching native LLVM/libgit2/OpenSSL/CRT inputs remain required. No physical-machine coverage is implied for virtual or compile-only targets.

Ecosystem API versions: nllvm 0.41.0, ngit 0.2.0, json 0.20.0, yaml 0.19.0, net_core 0.2.0, tls 0.3.0, http 0.2.0 and http_tls 0.2.0. Public manifests retain immutable Git dependencies; local workspaces provide overrides. Ecosystem source tags/publication and active bootstrap promotion remain separate operations. String interpolation and regex remain planned for 1.0.6.

Windows LLVM linker/archiver invocation uses response files to support large object worksets. Original qualification failures and focused repair provenance remain retained internally. All release gates must pass before publication. Binaries are ad-hoc signed where applicable, without Developer ID signing or notarization.

Native qualification covers G1/G2 identity and the complete G2 suites once, plus bootstrap-built tool units once. Publication preserves accepted bytes. Runtime execution/compile-only levels are recorded per target. macOS x86_64 currently uses Rosetta. Compile-only does not establish runtime execution or a linked host SDK.
